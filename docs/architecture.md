# Архитектура связки «Веб-панель + MAX Bot + Hermes» для детского бассейна

## 1. Контекст и боли

- **Исходная ситуация:** много клиентов (дети + родители), несколько тренеров и всего **2 администратора**.
- **Текущие инструменты:**
  1. **Бумажный журнал** для расписания — нельзя вести вдвоём, легко допустить накладку по времени/дорожке, тренеры постоянно спрашивают администраторов «кто у меня сегодня?».
  2. **Excel-таблицы** для базы и абонементов — ручное списание занятий, ручной контроль заморозок по болезни и сроков медсправок.
  3. **Мессенджер MAX в одном Android-телефоне** — переписка привязана к смартфону, при смене администратора теряется контекст, медленный ввод.

> **Быстрый бесплатный шаг уже на сегодня (0 ₽):** открыть `web.max.ru` на рабочем ПК администраторов (вход по QR-коду из мобильного MAX). Переписка становится в 2–3 раза быстрее без смены инструментов.

## 3. Архитектура 3 независимых слоёв

Главный принцип: **учёт, расписание и абонементы живут в жёстком коде и БД**, а не в нейросети. Если API LLM или Hermes отключится, веб-панель и бот продолжат работать без сбоев.

1. **Слой 1 — Ядро (Веб-панель + Backend API + SQLite WAL)**
   - Жёсткая бизнес-логика без LLM: защита от двойной записи, атомарное списание абонемента, аудит-лог.
   - Работает на недорогом VPS (~400–600 ₽/мес) с ежедневным автобэкапом.
2. **Слой 2 — MAX Bot Service (`platform-api2.max.ru`)**
   - Официальный бот для подтверждения визитов, отправки фото справок, остатка абонементов и утренних списков тренерам.
   - Живые нестандартные диалоги девочки ведут с ПК через `web.max.ru`.
3. **Слой 3 — Hermes Agent**
   - **`no-agent` cron (0 ₽ на токены):** чистые скрипты по расписанию (напоминания в `19:00`, списки тренерам в `08:00`, проверка справок/абонементов в `10:00`, вечерняя сводка владельцу в `21:00`, бэкап SQLite в `03:00`).
   - **LLM-режим (точечно):** разбор свободных сообщений/голосовых и фото справок от родителей, подбор свободного окна переноса, автоответы на FAQ, ответы на аналитические вопросы владельца.
   - **Изоляция безопасности:** у Hermes ограниченный API-ключ (`read` + `create_pending_action`). Все изменения в расписании или абонементах, предложенные агентом, попадают в `pending_actions` и применяются только после подтверждения администратором в 1 клик.

## 4. Модель данных (8 основных таблиц SQLite + аудит)

1. `parents` — родители: ФИО, телефон, `max_user_id`, заметки, флаг уведомлений.
2. `children` — дети: `parent_id`, ФИО, возраст, особенности (аллергия / страх воды), `med_cert_valid_until`, ссылка на фото справки.
3. `trainers` — тренеры: ФИО, телефон, `max_user_id`, ставка/правило расчёта ЗП, статус.
4. `lanes` — чаши / дорожки: название, макс. вместимость слота (`1` — индивидуалка/груднички, `N` — группа).
5. `subscriptions` — абонементы: `child_id`, тип (разовое / 4 / 8 / 12), `total`, `remaining`, `valid_until`, статус (`active / frozen / expired`).
6. `sessions` — слоты расписания: дата, время начала/конца, `trainer_id`, `lane_id`, формат (`individual / group`), лимит мест.
7. `bookings` — записи детей: `session_id`, `child_id`, `subscription_id`, статус (`scheduled / confirmed / attended / missed_charged / cancelled_free / frozen_illness`), автор и время правки.
8. `pending_actions` — очередь предложений Hermes для админов: исходный текст/фото от родителя, предложенное действие (перенос / заморозка / новая справка), статус (`pending / approved / rejected`).
9. `audit_log` — журнал всех значимых изменений с указанием актёра (Анна, Мария, MAX Bot, Hermes + админ).

**Ключевые предохранители:**
- Запрет двойной записи одного тренера на одно и то же время и переполнения дорожки.
- Уникальный ключ `(session_id, child_id)` и проверка идемпотентности исключают двойное списание с абонемента за один визит.
- Прозрачное переключение смены администраторов — видно, кто и когда внёс изменение.

## 5. Веб-панель администратора (4 экрана)

1. **«Сегодня / Расписание»** — сетка по времени и тренерам/дорожкам; индикаторы статуса MAX (🟢/🟡/🔴), остатка абонемента (⚠️ ≤1) и справки (🩺 <7 дней); отметка «Пришёл / Не пришёл» в 1 клик; боковой блок **«Предложения Hermes»** с кнопками «Подтвердить» / «Отклонить».
2. **«Клиенты и дети»** — быстрый поиск по фамилии/телефону, карточка семьи, остаток абонемента, срок справки, история визитов, импорт из Excel.
3. **«Абонементы»** — выдача, продление, заморозка, фильтр «заканчивается абонемент / истекает справка».
4. **«Тренеры и итоги»** — сводка проведённых занятий за день/период для прозрачного расчёта зарплаты.

## 7. Поэтапный план внедрения

1. **Этап 1 — Ядро + Веб-панель (MVP):** БД SQLite, 4 экрана для 2 администраторов, импорт базы из текущего Excel. Отказ от бумажного журнала.
2. **Этап 2 — MAX Bot (без LLM):** регистрация бота, напоминания с кнопками, утреннее расписание тренерам, приём фото справок.
3. **Этап 3 — Интеграция Hermes:** `no-agent` cron-отчёты владельцу, автоответчик по `FAQ.md` и очередь `pending_actions`.
4. **Этап 4 — Пилот (3–5 дней):** параллельная работа с бумажным журналом, доработка мелочей по обратной связи 2 администраторов, полный переход.

## 8. Опросник для владельца перед стартом разработки

1. Формат занятий: групповые секции, индивидуальные (грудничковое плавание) или оба формата? Сколько чаш / дорожек?
2. Сколько примерно активных детей и тренеров сейчас?
3. По каким правилам действуют абонементы и заморозки (нужна ли обязательная справка от врача, за сколько часов можно бесплатно отменить)?
4. Как рассчитывается зарплата тренеров (фикс за выход, ставка за занятие, % от стоимости)?
5. Какие колонки сейчас есть в Excel-таблице клиентов и как устроен бумажный журнал (обезличенный пример/фото)?
6. Нужна ли интеграция с онлайн-кассой / эквайрингом на старте или оплата пока фиксируется администратором вручную (перевод / наличные / терминал)?
